# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Rhythmos is a break-reminder tray/menu-bar app for Windows and macOS (Apple Silicon), written in Python 3.12 with Tkinter for windows and `pystray` + Pillow for the tray icon. Code and everything around it (comments, docstrings, identifiers, log messages, tests, build scripts, CI) is **English only**. Ukrainian appears only as localized user-facing text: `i18n.py`, the exercise texts in `exercises.py`, the installer's Ukrainian messages, and the README. Commits follow Conventional Commits (`feat(macos): …`, `fix: …`, `chore: release x.y.z`).

## Commands

```bash
python3 -m pip install -r requirements.txt -r requirements-build.txt
python3 src/rhythmos.py --open          # run from source, opening the main window
python3 -m pytest -q                  # all tests
python3 -m pytest -q tests/test_logic.py::test_postpone_limit   # single test
./build_mac.sh [version]              # dist/Rhythmos.app + dist/Rhythmos-<ver>-macos-<arch>.dmg
.\build.ps1 [-Version x.y.z]          # Windows: PyInstaller exe + Inno Setup installer
```

Dev/debug flags for `src/rhythmos.py`: `--open`, `--test-break` (trigger a break after 1.5 s), `--test-water`, `--smoke-test <dir>` (walks every window, saves screenshots plus `info.txt` with window/page sizes, then exits with a status code — CI runs it against the built app on both Windows and macOS and uploads `windows-smoke` / `macos-smoke`; look at those screenshots before tagging a release, macOS has broken layouts that Windows did not show). Installer-only flags that apply a setting and exit immediately: `--set-autostart=on|off`, `--set-language=uk|en`.

Lint with `python3 -m pyflakes src tests tools` (CI runs it; it also catches duplicate keys in the `i18n.py` dictionaries, which would silently override a string).

## Architecture

All source is in `src/` as flat modules (no package); tests add `src/` to `sys.path` and import `core`, `exercises`, `i18n` directly. Dependencies go one way: `core` ← `graphics` ← `widgets` ← `popups` / `main_window` ← `rhythmos`.

- **`core.py`** — all logic without Tk, and what tests cover: config (`DEFAULTS`, `SLIDERS` with `SLIDER_ZERO` "auto"/"off" positions, `migrate_config`, water profiles), the workday helpers (`workday_date`, `at_workday_minute`), `Scheduler` (person state, break countdown, reminders, persistence — see below), `build_workout`/`regroup_workout`/`build_break` (break steps that sum to an exact duration), `Stats` (per-day counters plus time lists such as `water_at`, keyed by the current workday via `Stats(today=…)`, and the per-day event log — see below), the pure event helpers (`event_spans`, `day_bounds`, `regularity`, `longest_work_stretch`, `absence_span`, `export_csv`), and layout maths (`split_balanced`, `main_layout`).
- **`graphics.py`** — the palette `C` and everything drawn with Pillow: tray ring, app icon, glasses, plates, dots, check mark. Tk does not anti-alias, so shapes are drawn supersampled (`smooth_image`) and cached as `PhotoImage`s.
- **`widgets.py`** — custom Tk widgets (`flat_button`, `card`, `Slider`, `Toggle`, `ScrollArea`, `demo_badge`). Built from `Label`/`Canvas` because `tk.Button` on macOS ignores colours. It also holds the spacing scale (`UNIT` = 4 px; `TIGHT`, `ITEM`, `CARD`, `CARD_PAD`, `HEAD_GAP`, `EDGE`): every padding in the UI is a multiple of `UNIT`, following betterwebtype.com (vertical rhythm; proximity — a label is closer to its control than to the next setting, cards are farther apart still). Use these constants instead of raw pixel values.
- **`popups.py`** — `Popups` mixin of `App`: break warning and break screens, water/meal/day-end windows and toasts stacked in the screen corner (`corner_window`, `place_in_corner`, `popup_head`, `popup_buttons`). A window that asks the person something never closes by itself with an implied answer (the person may have gone to get water): it waits (`show_toast(timeout_ms=None)`), and one pushed out by another notification asks again later (snooze) rather than recording "later" or "missed".
- **`main_window.py`** — `MainWindow` mixin of `App`: the main window sized to the screen's work area (`main_layout`; pages in `ScrollArea`s scroll when they don't fit) with the Status, Statistics and Settings pages. `refresh_main` runs every second but redraws the Status page only while it is visible.
- **`rhythmos.py`** — entry point and `App(Popups, MainWindow)`: tray, the per-second loop, action queue, update checks, `--smoke-test`. `__version__` lives here.
- **`system.py`** — every OS-specific concern behind `IS_WINDOWS`/`IS_MAC` branches: data dir, fonts, autostart (Windows Task Scheduler via PowerShell; macOS LaunchAgent plist), single-instance lock (named mutex vs `fcntl`) and "show window" signalling, monitors, sounds, notifications, tray startup, system language. Put new platform-dependent code here, not in the UI modules.
- **`exercises.py`** — the exercise library. Each entry is `(kind, group, level, (title_uk, text_uk), (title_en, text_en))`; `kind` is `mini`/`active`/`long`/`workout`, `group` is one of `GROUPS`. Pools are filtered by kind/group/level and localized at selection time.
- **`updates.py`** — hourly (and on opening the main window) check of the latest GitHub release (`AirFast/Rhythmos`, needs the repo to be public); `App.check_updates` runs it in a thread and posts the result to the queue. Uses `certifi` because frozen macOS builds have no system CA bundle.
- **`i18n.py`** — `STRINGS` (UI) and `CONTENT` (warmup/cooldown, water and meal tips) for `uk` and `en`, plus plural-aware formatters (`fmt_minutes`, `fmt_glasses`, …). Language is module-global state (`set_language`). Tests enforce that both languages have identical keys/shape, every slider has labels in both, and every group has exercises for every break type and level — adding a string, slider, or exercise means updating both languages.

### Runtime model

- Tk runs on the main thread. Tray menu callbacks must not touch Tk directly — they `queue.put()` an action, and `App.process_queue` (polled every 100 ms via `root.after`) dispatches it. On Windows pystray runs its own loop in a daemon thread; on macOS both must live on the main thread, so pystray uses `run_detached` on the shared `NSApplication` that Tk already runs (`system.start_tray`/`make_tray_icon`).
- `App.loop` ticks every second using `time.monotonic()` deltas clamped to 5 s, so sleep time isn't counted as work. Before each tick `App.sync_day()` passes today's glasses, workday end and work seconds to `Scheduler.update_day`, then calls `Scheduler.tick(seconds, now=None, idle=…, busy=App.is_busy())`. It returns event names (`"warn"`, `"break"`, `"break_held"`, `"water"`, `"meal"`, `"meal_over"`, `"day_end"`, `"overwork"`, `"day_continued"`, `"back"`). Tests drive it directly with `tick(1, now=…)` loops and always pass `now`.
- **Person state.** `Scheduler.mode` is one of `WORKING`, `BREAK`, `EATING`, `PAUSED` (timed pause), `FINISHED` ("Finish the day", until 06:00 — `MORNING`). `AWAY` comes from idle (`idle >= away_after()`) and overlays the mode (`Scheduler.state`), so a pause's deadline survives an absence. Only methods change the mode (`start_break`, `finish_break`, `postpone`, `pause`, `resume`, `meal_answered`, `finish_meal`). `FREEZES` is the single table of what each state stops: the break countdown, the water countdown, wall-clock reminders. Read-only properties (`in_break`, `paused`, `paused_until`, `eating`, `pause_water`, `meal_open`, …) serve the UI. Coming back from an absence restarts the break countdown; an absence of at least 2 × the long break also resets the long-break cadence. A skipped long break comes back once (`long_skipped`). While `busy`, warn and break wait for at most `BREAK_HOLD_MAX_MIN`.
- **Reminders.** Water (work-time countdown, smart pacing via `water_interval`), breakfast/lunch/dinner, the post-meal "continue?" prompt, day end and the overwork limit are all `Reminder` subclasses. `poll()` applies the same rules to each of them: a gate frozen by the state, `quiet()` (disabled, not a workday, already answered, day finished, goal reached), open → wait, `waits` groups (day end waits for meals), snooze with staleness (`stale`), then the reminder's own `triggered()`. "Today" is the real calendar day, 00:00–24:00 (`workday_date`).
- **Persistence.** `Scheduler.snapshot(now)` → `state.json` once a minute and on quit. `restore(data, now)` reloads it at startup if it is from the same workday and at most `STATE_MAX_AGE_H` old. An interrupted break resumes in a minute, and a long gap counts as an absence. `App.restore_today()` additionally applies what stats already know (`restore_day`), so a missing `state.json` still works.
- **Event log.** Each day in the statistics also has `"events"`: dicts with `type` and `at` (minute of the calendar day from `day_minute`). Types: `break` (`kind` mini/long, `result` done/skipped/postponed, `sec`), `away` (`to`), `pause` (`to`, `kind` timed/eating/finished, `meal`), `held` (`to`, `reason`), `water`, `meal` (`meal`), `day_start`, `day_end`, `overwork`. Write with `Stats.log(type, at, replace=…, **fields)` (one disk write; `replace=()` keeps one event of that type), close spans with `Stats.close`. `App.track_spans()` opens/closes pause and held spans from the scheduler state (open spans have `to: None`; `adopt_open_spans` continues or closes them after a restart), `"back"` logs an absence from `Scheduler.last_away`, and popups log breaks, water and meals. The counters are still written (old days have no events); the Status timeline and the regularity facts on the Statistics chart come from the log, and "Export CSV" writes days plus `<name>-events.csv`.
- The first input of the day after `EARLIEST_START` (04:00) is stored as `day_start`; `workday_start` (config, 0 = auto) overrides it for the workday span. `day_start` is the earliest known activity of the day (`first_activity`). After "Finish the day", `FINISH_GRACE_MIN` of continuous work un-finishes the day (`day_continued`): the logged `day_end` is removed and the "Finish the day" button returns.
- User data (`config.json`, `stats/<YYYY-MM>.json` — statistics one file per month, so a write only rewrites its month; the single `stats.json` of versions before 2.16 is split once by `Stats.load` and kept as `stats-before-2.16.json` — `state.json`, `rhythmos.log`) lives in `system.data_dir()` (`%APPDATA%\Rhythmos` / `~/Library/Application Support/Rhythmos`). Frozen builds have no console, so stderr is redirected to `rhythmos.log` very early in `rhythmos.py` (before importing pystray) and uncaught errors are logged rather than raised.

## Release

Version is the single `__version__` in `src/rhythmos.py` (build scripts read it). Every push to `main` runs `.github/workflows/release.yml` (lint, tests, Windows installer + smoke test, macOS dmg + smoke test + self-update test); pushing a `v*` tag additionally publishes a GitHub Release with both installers. The macOS app is ad-hoc signed and made a menu-bar-only app (`LSUIElement`) by `build_mac.sh`; on first frozen launch it asks whether to open at login (there is no installer checkbox) — the app never changes settings on its own; `save_config` keeps values derived from the Female/Male water norm out of config.json. `assets/` icons are regenerated by `tools/make_icon.py` during builds.
