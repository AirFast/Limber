# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository. It is the shared memory of every session (the owner works from a Windows and a macOS machine): anything that must hold for all sessions belongs here, not in a machine's local Claude memory.

## Project

Rhythmos is a break-reminder tray/menu-bar app for Windows and macOS (Apple Silicon), written in Python 3.12 with Tkinter for windows and `pystray` + Pillow for the tray icon. Code and everything around it (comments, docstrings, identifiers, log messages, tests, build scripts, CI) is **English only**. Ukrainian appears only as localized user-facing text: `i18n.py`, the exercise texts in `exercises.py`, the installer's Ukrainian messages, and the README. Commits follow Conventional Commits (`feat(macos): …`, `fix: …`, `chore: release x.y.z`).

## Working with the owner

- **Reply in Ukrainian**, always. Code, commits and docs stay English (above).
- **Never decide for the person** — the core product rule:
  - The app never changes settings on its own. Adaptive logic (smart water pacing, holding breaks during calls, natural breaks on absence, workday detection) may change *runtime* timing only and never writes config.json; values derived from a mode the person chose (the Female/Male water norm) are computed at runtime and kept out of config.json by `save_config`. Ideas like "you usually eat at 13:40" are offered as suggestions confirmed with a click.
  - It never answers for the person either. A window that asks something (water, meals, "Continue?", day end, work limit, autostart) never closes by itself with an implied answer — the person may have gone to get water, and a vanished window once logged a missed glass. It waits; one pushed out by another notification asks again later (snooze), never records "later"/"missed"/"skip".
- **Commit, push and release without asking**, but only after testing on both OSes (see Testing and release). A tag ships an auto-update to every user, so a release must be checked on Windows *and* macOS. Never touch the owner's installed, running copy of the app: test from source with `tools/smoke_local.py`.
- **Apply a convention to the whole project at once**, not only to the code being touched (the owner was annoyed when the English-only rule was applied piecemeal).
- **UI spacing** follows betterwebtype.com (vertical rhythm, proximity): only the constants in `widgets.py`, roomy rather than tight; the main window keeps its planned width (1280/1080/900).
- **Ukrainian text must sound natural**, not translated: questions are phrased as a person would ask them ("Було смачно?", not "Смачного було?"), no Russianisms ("сідничний", not "ягідичний"), one form of address (always "ви"). A label and its value must read as one phrase ("Ліміт відкладань: жодного").
- **Status vs Statistics.** Status is the live main window plus a quick but detailed look at any of the last 7 days (the day card); Statistics is the chart over 7/30 days for trends. New per-day facts go to the day card, period totals to Statistics.

## Keeping this file current

This file is the single place for everything about the app: rules from the owner, decisions and why they were made, the logic of features, pitfalls found (with the version they bit in), the workflow. **Every session updates it in the same commit as the change** — a new rule from the owner, a new feature's logic, a bug's root cause worth remembering, a changed workflow. No separate `.md` files for rules or notes and no machine-local Claude memory for anything shared (the other machine can't see it); `README.md` stays the users' document. If this file grows unwieldy, split it into files under `docs/` imported here with `@docs/<name>.md`, never into notes outside the repo.

## Working from two sessions (Windows and macOS)

Git `main` is the only sync point between the sessions; they cannot see each other otherwise.

**Both sessions**
- `git pull --rebase` before starting a task and again before every push; commit small and push often. A rejected push means the other session pushed: rebase on `origin/main` (never force-push), rerun lint and tests, push again.
- Read `git log` since your last pull before starting: the other session's commits explain what changed and why.
- Findings for the other machine go to GitHub Issues (`gh issue create --label macos` or `--label windows`): what happened, steps, a screenshot, the version (`__version__` / window title). The fixing commit closes it (`fixes #N`).
- Anything learned that the other session needs (a rule, a pitfall, a platform quirk) goes into this file, not into local memory.

**Windows session** — main development and *all releases*
- Develops features and fixes, tests on Windows (`tools/smoke_local.py`) and on macOS through CI screenshots, and cuts every release (version bump + `v*` tag), including fixes pushed by the macOS session.
- Before a release, checks open `macos` issues: a release must not ship a known macOS regression.

**macOS session** — real-Mac testing and macOS-only fixes, never releases
1. Start: `git pull --rebase`; note the latest released version (`gh release view`) and whether the installed app is on it (it updates itself hourly; the window title shows the version).
2. Test the installed release on the real Mac, focusing on what CI cannot check: the menu-bar icon and menu, reminder windows in the bottom right corner and above the main window, the main window opening with a page chosen, idle and away detection with real input and after sleep/wake, a break held during a real call (camera, microphone, screen sharing), fullscreen break screens on every monitor (notch/menu bar), sounds, open at login, the self-update from the previous version. `python3 tools/smoke_local.py` tests the current source next to the installed app.
3. A problem → a GitHub issue with the `macos` label. If it is macOS-only and the fix belongs in `system.py` or macOS window handling, fix it: tests and lint pass, `tools/smoke_local.py` looks right, commit `fix(macos): …` with `fixes #N`, push to `main`. Do not bump `__version__` and do not tag — the Windows session releases it.
4. A problem in shared logic (`core.py`, the UI on both OSes) → fix it the same way if it's clear and small, otherwise leave the issue for the Windows session.
5. Never touch the owner's installed copy's data or settings; test from source with `tools/smoke_local.py`.

## Commands

```bash
python3 -m pip install -r requirements.txt -r requirements-build.txt
python3 src/rhythmos.py --open          # run from source, opening the main window
python3 -m pytest -q                  # all tests
python3 -m pytest -q tests/test_logic.py::test_postpone_limit   # single test
python3 tools/smoke_local.py [out]    # smoke test from source next to the installed app (copy of real data)
./build_mac.sh [version]              # dist/Rhythmos.app + dist/Rhythmos-<ver>-macos-<arch>.dmg
.\build.ps1 [-Version x.y.z]          # Windows: PyInstaller exe + Inno Setup installer
```

Dev/debug flags for `src/rhythmos.py`: `--open`, `--test-break` (trigger a break after 1.5 s), `--test-water`, `--smoke-test <dir>` (walks every window, saves screenshots plus `info.txt` with window/page sizes and reminder window positions, then exits with a status code). Installer-only flags that apply a setting and exit immediately: `--set-autostart=on|off`, `--set-language=uk|en`.

Lint with `python3 -m pyflakes src tests tools` (CI runs it; it also catches duplicate keys in the `i18n.py` dictionaries, which would silently override a string).

## Architecture

All source is in `src/` as flat modules (no package); tests add `src/` to `sys.path` and import `core`, `exercises`, `i18n` directly. Dependencies go one way: `core` ← `graphics` ← `widgets` ← `popups` / `main_window` ← `rhythmos`.

- **`core.py`** — all logic without Tk, and what tests cover: config (`DEFAULTS`, `SLIDERS` with `SLIDER_ZERO` "auto"/"off" positions, `migrate_config`, water profiles), the workday helpers (`workday_date`, `at_workday_minute`), `Scheduler` (person state, break countdown, reminders, persistence — see below), `build_workout`/`regroup_workout`/`build_break` (break steps that sum to an exact duration), `Stats` (per-day counters plus time lists such as `water_at`, keyed by the current workday via `Stats(today=…)`, and the per-day event log — see below), the pure event helpers (`event_spans`, `day_bounds`, `regularity`, `current_stretch`, `longest_work_stretch`, `absence_span`, `export_csv`), and layout maths (`split_balanced`, `main_layout`).
- **`graphics.py`** — the palette `C` and everything drawn with Pillow: tray ring, app icon, glasses, plates, dots, check mark. Tk does not anti-alias, so shapes are drawn supersampled (`smooth_image`, `SUPERSAMPLE` = 4, scaled down with `Image.reduce` — a box average that looks the same as LANCZOS and is about 3× faster) and cached as `PhotoImage`s.
- **`widgets.py`** — custom Tk widgets (`flat_button`, `card`, `Slider`, `Toggle`, `ScrollArea`, `demo_badge`). Built from `Label`/`Canvas` because `tk.Button` on macOS ignores colours. It also holds the spacing scale (`UNIT` = 4 px; `TIGHT`, `ITEM`, `CARD`, `CARD_PAD`, `HEAD_GAP`, `EDGE`): every padding in the UI is a multiple of `UNIT`, following betterwebtype.com (vertical rhythm; proximity — a label is closer to its control than to the next setting, cards are farther apart still). Use these constants instead of raw pixel values.
- **`popups.py`** — `Popups` mixin of `App`: break warning and break screens, water/meal/day-end windows and toasts in the **bottom right corner** of the work area, stacked upwards when several are open (`corner`, `corner_window`, `place_in_corner`, `popup_head`, `popup_buttons`). Asking windows wait for an answer (`show_toast(timeout_ms=None)`; only demos and plain information close by themselves); one pushed out by another notification asks again later (snooze). The water window logs `water_missed` only on an explicit "Later"; a glass added on Status or from the tray closes it as drunk.
- **`main_window.py`** — `MainWindow` mixin of `App`: the main window sized to the screen's work area (`main_layout`; pages in `ScrollArea`s scroll when they don't fit) with the Status, Statistics and Settings pages. `refresh_main` runs every second but redraws the Status page only while it is visible (the ring only in 0.2% steps, the timeline only when its key changes). On Status, Water and Meals cards and the ring are always today and interactive; the **day card** below has a switch of the last `STATUS_DAYS` (7) days instead of a heading (`day_back`, `set_status_day`, `refresh_day_chips`): its metrics and timeline show the chosen day — for a past day what happened (no "now", no plans; "min without a break" becomes that day's longest stretch; days before the event log show "—"). It returns to today on a new day and when the window reopens. Meal marks use `meal_time`: when eaten, else the time a snooze moved it to, else the planned time.
- **`rhythmos.py`** — entry point and `App(Popups, MainWindow)`: tray, the per-second loop, action queue, update checks, `--smoke-test`. `__version__` lives here.
- **`system.py`** — every OS-specific concern behind `IS_WINDOWS`/`IS_MAC` branches: data dir, fonts, cursors (`HAND`), autostart (Windows Task Scheduler via PowerShell; macOS LaunchAgent plist), single-instance lock (named mutex vs `fcntl` lock file in the data dir) and "show window" signalling, monitors, work area, sounds, notifications, tray startup, system language, `keep_on_top`. Put new platform-dependent code here, not in the UI modules.
  - `keep_on_top(win, geometry)` places every reminder window and break screen: **`-topmost` first, then the geometry**. Set after the geometry on a frameless window not yet on screen, `-topmost` moves it to the screen's top left corner (Windows and macOS alike — this shipped once in 2.16.5). On macOS `-topmost` given before the window is shown is also lost, so the main window opened later covered reminders; there both are set again, in the same order, once the window is on screen.
- **`exercises.py`** — the exercise library. Each entry is `(kind, group, level, (title_uk, text_uk), (title_en, text_en))`; `kind` is `mini`/`active`/`long`/`workout`, `group` is one of `GROUPS`. Pools are filtered by kind/group/level and localized at selection time.
- **`updates.py`** — hourly (and on opening the main window) check of the latest GitHub release (`AirFast/Rhythmos`, needs the repo to be public); `App.check_updates` runs it in a thread and posts the result to the queue. Uses `certifi` because frozen macOS builds have no system CA bundle.
- **`i18n.py`** — `STRINGS` (UI) and `CONTENT` (warmup/cooldown, water and meal tips) for `uk` and `en`, plus plural-aware formatters (`fmt_minutes`, `fmt_glasses`, …). Language is module-global state (`set_language`). Tests enforce that both languages have identical keys/shape, every slider has labels in both, and every group has exercises for every break type and level — adding a string, slider, or exercise means updating both languages.
- **`tools/`** — `make_icon.py` (icons for builds), `seed_stats.py` (a week of statistics in the pre-2.16 format for CI; `--check` verifies the migration), `smoke_local.py` (the smoke test from source with a copy of the real data in a temporary folder and its own single-instance lock, so it runs next to the installed app).

### Runtime model

- Tk runs on the main thread. Tray menu callbacks must not touch Tk directly — they `queue.put()` an action, and `App.process_queue` (polled every 100 ms via `root.after`) dispatches it. On Windows pystray runs its own loop in a daemon thread; on macOS both must live on the main thread, so pystray uses `run_detached` on the shared `NSApplication` that Tk already runs (`system.start_tray`/`make_tray_icon`).
- `App.loop` ticks every second using `time.monotonic()` deltas clamped to 5 s, so sleep time isn't counted as work. Before each tick `App.sync_day()` passes today's glasses, workday end and work seconds to `Scheduler.update_day`, then calls `Scheduler.tick(seconds, now=None, idle=…, busy=App.is_busy())`. It returns event names (`"warn"`, `"break"`, `"break_held"`, `"water"`, `"meal"`, `"meal_over"`, `"day_end"`, `"overwork"`, `"day_continued"`, `"back"`). Tests drive it directly with `tick(1, now=…)` loops and always pass `now`. With the main window closed a tick costs about 1 ms; keep it that way (the OS is asked about calls only when a break is near: `is_busy`).
- **Person state.** `Scheduler.mode` is one of `WORKING`, `BREAK`, `EATING`, `PAUSED` (timed pause), `FINISHED` ("Finish the day", until 06:00 — `MORNING`). `AWAY` comes from idle (`idle >= away_after()`) and overlays the mode (`Scheduler.state`), so a pause's deadline survives an absence. Only methods change the mode (`start_break`, `finish_break`, `postpone`, `pause`, `resume`, `meal_answered`, `finish_meal`). `FREEZES` is the single table of what each state stops: the break countdown, the water countdown, wall-clock reminders. Read-only properties (`in_break`, `paused`, `paused_until`, `eating`, `pause_water`, `meal_open`, …) serve the UI. Coming back from an absence restarts the break countdown; an absence of at least 2 × the long break also resets the long-break cadence. A skipped long break comes back once (`long_skipped`). While `busy`, warn and break wait for at most `BREAK_HOLD_MAX_MIN`. A break that ran to its end while the person was away counts as an absence, not a done break.
- **Reminders.** Water (work-time countdown, smart pacing via `water_interval`), breakfast/lunch/dinner, the post-meal "continue?" prompt, day end and the overwork limit are all `Reminder` subclasses. `poll()` applies the same rules to each of them: a gate frozen by the state, `quiet()` (disabled, not a workday, already answered, day finished, goal reached), open → wait, `waits` groups (day end waits for meals), snooze with staleness (`stale`), then the reminder's own `triggered()`. "snooze" postpones by `snooze_min` (meals 15, day end and work limit 30) and keeps `moved_to`, so a snoozed meal shows its new time everywhere, also once its window is open again (`meal_state` returns it for "open"); any other answer is final for the day. "Today" is the real calendar day, 00:00–24:00 (`workday_date`).
- **Persistence.** `Scheduler.snapshot(now)` → `state.json` once a minute and on quit. `restore(data, now)` reloads it at startup if it is from the same workday and at most `STATE_MAX_AGE_H` old. An interrupted break resumes in a minute, and a long gap counts as an absence. `App.restore_today()` additionally applies what stats already know (`restore_day`), so a missing `state.json` still works.
- **Event log.** Each day in the statistics also has `"events"`: dicts with `type` and `at` (minute of the calendar day from `day_minute`). Types: `break` (`kind` mini/long, `result` done/skipped/postponed, `sec`), `away` (`to`), `pause` (`to`, `kind` timed/eating/finished, `meal`), `held` (`to`, `reason`), `water`, `water_missed`, `meal` (`meal`), `day_start`, `day_end`, `overwork`. Write with `Stats.log(type, at, replace=…, **fields)` (one disk write; `replace=()` keeps one event of that type), close spans with `Stats.close`. `App.track_spans()` opens/closes pause and held spans from the scheduler state (open spans have `to: None`; `adopt_open_spans` continues or closes them after a restart), `"back"` logs an absence from `Scheduler.last_away`, and popups log breaks, water and meals. The counters are still written (old days have no events); the Status timeline and the regularity facts on the Statistics chart come from the log, and "Export CSV" writes days plus `<name>-events.csv`.
- The first input of the day after `EARLIEST_START` (04:00) is stored as `day_start`; `workday_start` (config, 0 = auto) overrides it for the workday span. `day_start` is the earliest known activity of the day (`first_activity`). After "Finish the day", "Continue" (`Scheduler.resume` returns True) un-finishes the day at once, and so does `FINISH_GRACE_MIN` of continuous work (`day_continued`); both go through `App.continue_day`: the logged `day_end` is removed and the "Finish the day" button returns. A day continued before its end time gets the day-end question back at that time.
- **User data** lives in `system.data_dir()` (`%APPDATA%\Rhythmos` / `~/Library/Application Support/Rhythmos`): `config.json`, `stats/<YYYY-MM>.json`, `state.json`, `rhythmos.log`. Statistics are one compact file per month: every write (each minute for work time, and on every logged event) rewrites only its month, so it stays a few ms however long the history is — one indented file would be ~4.6 MB and 170 ms of frozen UI per write after a year. The single `stats.json` of versions before 2.16 is split once by `Stats.load` (into a temporary folder renamed at the end, so a crash loses nothing) and kept as `stats-before-2.16.json`. Never delete user data. Frozen builds have no console, so stderr is redirected to `rhythmos.log` very early in `rhythmos.py` (before importing pystray) and uncaught errors are logged rather than raised. On Windows such a build has `sys.stderr = None`, but on macOS an app started from Finder or at login has a real stderr on `/dev/null`: until 2.16.6 the redirect checked only for `None`, so on the Mac Tk callback tracebacks and self-update messages never reached the log (#1). A frozen build started from a terminal (a tty) keeps printing; the CI smoke test is not a tty, so it prints the log's tail itself.

## Testing and release

Version is the single `__version__` in `src/rhythmos.py` (build scripts read it). Every push to `main` runs `.github/workflows/release.yml`: lint and tests on both OSes, the Windows installer and the macOS dmg, then on each the built app's smoke test — after `tools/seed_stats.py` seeds a week of pre-2.16 statistics, so the migration (checked with `--check`) and filled statistics/past-day timelines are exercised — and on macOS a self-update test (a copy pretending to be 0.0.1 downloads the latest release, replaces itself and restarts). The smoke test fails if a water, meal or day-end window is not in the bottom right corner. Pushing a `v*` tag additionally publishes a GitHub Release with both installers.

Release checklist (Windows session):
1. `python -m pyflakes src tests tools`, `python -m pytest -q`, and `python tools/smoke_local.py` — look at its screenshots.
2. Push to `main`, wait for the workflow (`gh run watch`), download `macos-smoke` and `windows-smoke` (`gh run download <id> -n macos-smoke`) and actually look at the screenshots — macOS has shown broken layouts that Windows did not, and real reminders firing during the run show up there too.
3. Bump `__version__`, commit `chore: release x.y.z`, tag `vx.y.z`, push both, wait for the tag's run and check the release has both installers (`gh release view vx.y.z`). Patch for fixes, minor for features or storage changes.

The macOS app is ad-hoc signed and made a menu-bar-only app (`LSUIElement`) by `build_mac.sh`; on first frozen launch it asks whether to open at login (there is no installer checkbox). `assets/` icons are regenerated by `tools/make_icon.py` during builds.
